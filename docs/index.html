The problem

FHIR works. Using it with AI doesn't — out of the box.

FHIR R4 is the standard for exchanging clinical records, but connecting a language model to it directly runs into two hard problems.

  • Search"Adolph Smith" returns 0 results. The name must match one stored value exactly from the beginning — a phrase search doesn't work.
  • Search"a1c" misses "Hemoglobin A1c/Hemoglobin.total in Blood". Lab names must start with what you typed, not contain it.
  • SizeA patient summary takes six parallel API calls and returns ~200 KB of JSON — schema boilerplate, extensions, and coding systems the model never uses.
The fix

Smart matching and compact summaries on our side.

This server sits between the model and the FHIR server. It handles name and lab matching correctly, then returns compact summaries shaped for a model.

Architecture

Three things happen on every question

1

Policy & audit

Every call passes through policy filters that enforce a tool allowlist and write a tamper-evident audit record. Privacy mode — full or HIPAA Safe Harbor de-identified — is applied before data reaches the model.

2

Smart FHIR search

The longest word is sent as a FHIR prefix search. Every result is then checked against all stored names — official, maiden, aliases — with hyphens, apostrophes, and accents normalised. Lab names work the same way.

3

Compact summaries

Raw FHIR bundles are flattened to small JSON objects — only the fields a clinician would look at. The model receives 2.2 KB instead of 200 KB, which improves both accuracy and cost.

🔒 Read-only — only GET requests, no writes
🔑 SMART on FHIR — PKCE sign-in, token refresh, patient limit
📋 Audit log — hash-chained JSONL, tamper-evident
🏥 MCP protocol — works with Claude Desktop, Claude Code

Get started

Up in three commands

# Requires .NET 10 SDK (Arm64 on Apple Silicon) git clone https://github.com/marcsalot/fhir-mcp.git cd fhir-mcp && dotnet build dotnet run --project src/FhirMcp.Server -- search --name "reyna ziemann"

Connects to the SMART Health IT R4 sandbox by default — public synthetic data, no sign-in required. Then add it to Claude Desktop (Settings › Developer › Edit Config) or Claude Code (claude mcp add fhir ...).
