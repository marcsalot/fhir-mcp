The problem

FHIR works. Using it with AI doesn't — out of the box.

FHIR R4 is the standard for exchanging clinical data, but its default search behaviour and response sizes create real problems when you try to connect a language model to it.

  • Search "Adolph Smith" returns 0 results. The name must match one stored value exactly from the start.
  • Search "a1c" misses "Hemoglobin A1c/Hemoglobin.total in Blood". Lab names must match from the beginning.
  • Size A single patient summary takes six API calls and returns ~117 KB of JSON — mostly schema boilerplate.
The fix

Smart matching and compact summaries on our side.

This server sits between the AI and the FHIR server. It handles name and lab matching correctly, then returns compact summaries shaped for a model — not for a client that needs the full resource.

Architecture

Three things happen on every question

1

Policy & audit

Every tool call passes through policy filters that enforce an allowlist and write a tamper-evident audit record. Privacy mode (full or de-identified) is applied before any data reaches the model.

2

Smart FHIR search

Name matching is done on our side: the longest word is sent as a FHIR prefix search, then every result is checked against all stored names (official, maiden, aliases) with hyphens and accents normalised. Lab names work the same way.

3

Compact summaries

Raw FHIR bundles are flattened into small JSON objects — only the fields a person would actually look at. The model receives 2.2 KB instead of 117 KB, which improves both accuracy and cost.

Get started

Up in three commands

# Requires .NET 10 SDK git clone https://github.com/marcsalot/fhir-mcp.git cd fhir-mcp dotnet run --project src/FhirMcp.Server -- search --name "reyna ziemann"

Connects to the SMART Health IT R4 sandbox by default — public synthetic data, no sign-in required. Then add it to Claude Desktop or Claude Code to start asking questions.
