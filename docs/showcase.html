The problem

FHIR's defaults make it hard to use with AI

These aren't bugs — they're how the standard works. But they make a model-facing API impractical without a middleware layer that handles them.

Without this server
"Adolph Smith" → 0 results (phrase doesn't match any single name value)
"Sayed" → misses Al-Sayed (prefix search starts from "Al-")
"a1c" → 0 lab results ("Hemoglobin A1c/Hemoglobin.total…" doesn't start with "a1c")
Patient summary → ~200 KB across 6 API calls
With this server
"Adolph Smith" → found (longest word as prefix, every word checked against all names)
"Sayed" → Fatima Al-Sayed (name parts normalised, hyphens handled)
"a1c" → 5 results (word-matching fallback scans recent observations)
Patient summary → 2.2 KB, parallel fetches
Architecture

How it works

Every model question goes through three layers before FHIR data reaches Claude.

1

Policy filters

Enforce a tool allowlist, write a tamper-evident audit record for every call, and apply the privacy mode (full or HIPAA Safe Harbor de-identified).

2

Smart FHIR search

Sends the longest typed word as a FHIR prefix search. Checks every result against all stored names — official, maiden, aliases — with hyphens, apostrophes, and accents normalised. Falls back to :contains if nothing matches.

3

Compact summaries

Flattens FHIR bundles to small JSON — only the fields a clinician would look at. 200 KB becomes 2.2 KB. Six searches run in parallel. The model receives a compact, readable record.

Security & compliance
🔒

Read-only

Only GET requests. Patient IDs are validated against the FHIR format before entering a URL — ../Patient is rejected before a request is made.

📋

Audit log

Every tool call writes a JSON line with time, tool, outcome, patient IDs, item count, and a SHA-256 hash of the previous line — edits are detectable.

🔑

SMART on FHIR

PKCE sign-in, token refresh, one-patient limit. When scoped to a single patient, requests about anyone else are refused and audited as denied.

🏥

De-identified mode

HIPAA Safe Harbor applied before data reaches the model: names removed, dates reduced to year, ages over 89 shown as "90 or older".

Model evaluation

50 graded clinical questions

Medications, allergies, conditions, labs, vitals, visit history. Graded by deterministic rules — not another model — so the score is reproducible and every failure is listed for a person to review.

Get started

Clone, build, ask

# Requires .NET 10 SDK git clone https://github.com/marcsalot/fhir-mcp.git cd fhir-mcp && dotnet build && dotnet test dotnet run --project src/FhirMcp.Server -- search --name "reyna ziemann"
